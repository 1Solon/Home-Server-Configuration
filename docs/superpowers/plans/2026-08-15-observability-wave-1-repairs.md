# Observability Wave 1 Repairs Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Repair the existing Envoy, Gatus, Spegel, and Victoria Logs monitoring integrations before enabling any new metric sources.

**Architecture:** Correct the two Envoy namespace selectors and route all dashboard delivery through Grafana Operator. Reuse dashboard JSON already generated in the cluster; do not add a Grafana sidecar or duplicate dashboard data.

**Tech Stack:** Flux, Kustomize 5.8, Helm 4, Prometheus Operator, Grafana Operator, Spegel chart 0.7.4, Kubernetes

## Global Constraints

- This is rollout wave 1 of 4; do not begin wave 2 until the live gate passes.
- Do not push without explicit permission because a push triggers Flux reconciliation.
- Before every push, enumerate `origin/main..HEAD`; permission must cover every listed commit, not only this wave.
- Do not change Alertmanager receivers, Secrets, ExternalSecrets, or Discord credentials.
- Do not add a Grafana dashboard sidecar; GrafanaDashboard resources must select `dashboards: grafana`.
- Use `configMapRef` for dashboard JSON already generated by a chart or Kustomize.
- Manual Kubernetes patches are diagnostic only and must not become the implementation.

### Task 1: Correct Envoy monitor namespace discovery

**Files:**

- Modify: `kubernetes/networking/envoy-gateway/config/observability.yaml`
- Test: `kubernetes/networking/envoy-gateway/config/kustomization.yaml`

**Interfaces:**

- Consumes: Envoy proxy pods and the Envoy Gateway metrics Service in namespace `networking`.
- Produces: One PodMonitor and one ServiceMonitor whose namespace selectors both match `networking`.

- [ ] **Step 1: Prove the current selectors are wrong**

```bash
test "$(yq -r 'select(.kind == "PodMonitor") | .spec.namespaceSelector.matchNames[0]' kubernetes/networking/envoy-gateway/config/observability.yaml)" = networking && \
test "$(yq -r 'select(.kind == "ServiceMonitor") | .spec.namespaceSelector.matchNames[0]' kubernetes/networking/envoy-gateway/config/observability.yaml)" = networking
```

Expected: exit status `1`; both current values are `network`.

- [ ] **Step 2: Change both namespace selectors**

In both documents in `observability.yaml`, replace:

```yaml
  namespaceSelector:
    matchNames:
      - network
```

with:

```yaml
  namespaceSelector:
    matchNames:
      - networking
```

- [ ] **Step 3: Validate the corrected resources**

```bash
test "$(yq -r 'select(.kind == "PodMonitor") | .spec.namespaceSelector.matchNames[0]' kubernetes/networking/envoy-gateway/config/observability.yaml)" = networking
test "$(yq -r 'select(.kind == "ServiceMonitor") | .spec.namespaceSelector.matchNames[0]' kubernetes/networking/envoy-gateway/config/observability.yaml)" = networking
kustomize build kubernetes/networking/envoy-gateway/config >/dev/null
```

### Task 2: Replace the invalid Gatus dashboard references

**Files:**

- Modify: `kubernetes/observability/gatus/app/grafanadashboard.yaml`
- Test: `kubernetes/observability/gatus/app/kustomization.yaml`

**Interfaces:**

- Consumes: ConfigMap `gatus` with key `gatus.json`, generated by `kubernetes/observability/gatus/app/dashboard/kustomization.yaml`.
- Produces: One GrafanaDashboard named `gatus`; removes invalid `ups-aggregate` and `ups-status` resources.

- [ ] **Step 1: Prove the valid Gatus dashboard is absent**

```bash
kustomize build kubernetes/observability/gatus/app \
  | yq -e 'select(.kind == "GrafanaDashboard" and .metadata.name == "gatus" and .spec.configMapRef.name == "gatus" and .spec.configMapRef.key == "gatus.json")'
```

Expected: exit status `1`.

- [ ] **Step 2: Replace the dashboard manifest**

Set `grafanadashboard.yaml` to:

```yaml
---
# yaml-language-server: $schema=https://k8s-schemas.home-operations.com/grafana.integreatly.org/grafanadashboard_v1beta1.json
apiVersion: grafana.integreatly.org/v1beta1
kind: GrafanaDashboard
metadata:
  name: gatus
spec:
  allowCrossNamespaceImport: true
  instanceSelector:
    matchLabels:
      dashboards: grafana
  datasources:
    - datasourceName: prometheus
      inputName: DS_PROMETHEUS
  configMapRef:
    name: gatus
    key: gatus.json
```

- [ ] **Step 3: Validate that only the valid dashboard renders**

```bash
rendered_gatus_dashboard_count=$(kustomize build kubernetes/observability/gatus/app | yq -N 'select(.kind == "GrafanaDashboard") | .metadata.name' | wc -l)
test "$rendered_gatus_dashboard_count" -eq 1
kustomize build kubernetes/observability/gatus/app | yq -e 'select(.kind == "GrafanaDashboard" and .metadata.name == "gatus" and .spec.configMapRef.name == "gatus" and .spec.configMapRef.key == "gatus.json")'
git diff --check
```

Expected: exactly one GrafanaDashboard named `gatus`.

- [ ] **Step 4: Commit the Gatus repair**

```bash
git add kubernetes/observability/gatus/app/grafanadashboard.yaml
git commit -m "fix(gatus): repair dashboard import"
```

### Task 3: Switch Spegel to Grafana Operator delivery

**Files:**

- Modify: `kubernetes/infra/spegel/app/release.yaml`
- Test: Helm render of Spegel chart 0.7.4 and `kubernetes/infra/spegel/app/kustomization.yaml`

**Interfaces:**

- Consumes: Spegel's enabled ServiceMonitor and bundled dashboard JSON.
- Produces: A chart-rendered GrafanaDashboard selected by `dashboards: grafana`; no sidecar ConfigMap.

- [ ] **Step 1: Prove the current values do not render a GrafanaDashboard**

```bash
helm template spegel oci://ghcr.io/spegel-org/helm-charts/spegel --version 0.7.4 --namespace kube-system --values <(yq 'explode(.) | .spec.values' kubernetes/infra/spegel/app/release.yaml) | yq -e 'select(.kind == "GrafanaDashboard")'
```

Expected: exit status `1` because the current default mode is `Sidecar`.

- [ ] **Step 2: Configure Grafana Operator mode**

Replace the existing block with:

```yaml
    grafanaDashboard:
      enabled: true
      mode: GrafanaOperator
      grafanaOperator:
        allowCrossNamespaceImport: true
        matchLabels:
          dashboards: grafana
```

- [ ] **Step 3: Render and validate the operator resource**

```bash
helm template spegel oci://ghcr.io/spegel-org/helm-charts/spegel --version 0.7.4 --namespace kube-system --values <(yq 'explode(.) | .spec.values' kubernetes/infra/spegel/app/release.yaml) | yq -e 'select(.kind == "GrafanaDashboard" and .spec.instanceSelector.matchLabels.dashboards == "grafana" and .spec.allowCrossNamespaceImport == true)'
kustomize build kubernetes/infra/spegel/app >/dev/null
git diff --check
```

Expected: the chart renders one matching GrafanaDashboard.

- [ ] **Step 4: Commit the Spegel repair**

```bash
git add kubernetes/infra/spegel/app/release.yaml
git commit -m "fix(spegel): use Grafana Operator dashboard"
```
